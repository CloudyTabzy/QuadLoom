# QuadLoom 0.4.0 — Target quad count

Adds **Sizing → Target Quads** alongside the existing Density control. The target
is the total output count across parts and symmetry, with adaptive detail and
feature boundaries retained. Requested/achieved counts are visible in the panel;
constrained requests carry a warning. Presets retain the user's sizing mode/count,
and changing the target supports Quick Re-run and attribute transfer.

The target is approximate: existing feature/layout constraints and discrete
subdivisions can prevent exact counts, especially for very coarse requests.
Density remains the default and is checked against 0.3.0 for unchanged geometry.
The memory-limited worker and OOM hardening introduced in 0.3.0 remain enabled.

Artifact: `quadloom-0.4.0.zip` (production, fault injection disabled), attached to the v0.4.0 release.
Validation passed: Rust 321 all-features / 318 default (6 ignored each), both
clippy configurations, 117 Python tests and 49 Blender scenarios. The production
ZIP then passed version/fault-injection rejection checks and nine Blender smoke
scenarios, including target mode, presets, cache, attributes, undo and GUI remesh.
Builds used one Cargo job after freeing idle search-tool memory; shipping compiler
settings were unchanged.

Six-model Density output is byte-identical to 0.3.0. All six 8,000-quad requests
were within 4.1%. Across all 18 requests, 13 met the reporting tolerance; some
coarse CAD/organic cases missed substantially (bunny 2,000 → 1,560). Low-count
outputs can have poor geometric quality and targeting can add substantial solver
time. See the [full measured results](../../benchmark/reports/2026-10-24-target-count.md).
